# Static inputs — Des Plaines / Illinois (HUC8 07120004)

Everything that is identical across all shallow-water runs: the terrain, roughness,
initial state and gauge positions used by `run_hipims_event.py`, plus the derived DEM array
the trajectories are stored on.

```
static/
├── dem_5070.tif                          11.3 MB   terrain, EPSG:5070 (unburned)
├── landcover_5070.tif                     1.7 MB   NLCD land cover
├── gage_index_mapping_with_lat_lon.csv    2.2 kB   32 gauge positions
├── initial_condition/
│   ├── h_0.asc.gz                         5.6 MB   initial water depth (gzip)
│   ├── hUx_0.asc.gz                       3.9 MB   initial x-momentum (gzip)
│   └── hUy_0.asc.gz                       3.9 MB   initial y-momentum (gzip)
└── SHA256SUMS
```

**Not included, because they are derived and regenerated by the simulation scripts:** `DEM.npy` (202 MB; written by `collect_training_data.py`, described below) and `landcover_5070_processed.tif` (67 MB; written by `run_hipims_event.py` on first use). The initial-condition grids are gzip-compressed; `numpy.loadtxt`, which the scripts use, reads `.asc.gz` directly.

## What the simulator reads

Running `preprocessing/simulation/run_hipims_event.py` with its default arguments (`burned_dem=0`,
`variable_manning=0`, `resolution=30`, `filling_hours=0`) opens exactly these files, plus
one per-event rainfall `.nc` from `data/forcings/`:

| File | Used for |
|---|---|
| `dem_5070.tif` | terrain; **also loaded a second time as the rain-mask template** (line 158) |
| `landcover_5070_processed.tif` | binary water/land → Manning 0.02 (water) / 0.05 (land) |
| `initial_condition/h_0.asc.gz`, `hUx_0.asc.gz`, `hUy_0.asc.gz` | initial state |
| `gage_index_mapping_with_lat_lon.csv` | 32 gauge positions, read from `x_proj`/`y_proj` |

`landcover_5070.tif` is not read at run time while the processed version exists — the script
derives and writes `landcover_5070_processed.tif` from it only when that file is absent
(`landcover == 11 or 12 → 1, else 0`). It is deposited because it is the true source.

## The runs do not start dry

**`simulation_config.json` in every event folder records `"filling_strategy": "dry"` and
`"initial_waterdepth": 0.0`. Both are inert.** `preprocessing/simulation/run_hipims_event.py` loads
`initial_condition/*.asc.gz` unconditionally; the `initial_waterdepth` branch
above them is commented out. The actual initial state, measured over the 4 188 840 active
cells:

| | min | max | mean | non-zero cells |
|---|---|---|---|---|
| `h_0` | 8e-06 m | 5.0328 m | 0.0366 m | **100%** |
| `hUx_0` | −4.6121 | 4.8987 | −8.49e-05 | 23.63% |
| `hUy_0` | −7.9204 | 7.9645 | −6.81e-04 | 23.31% |

Every active cell begins wet and about a quarter carry momentum — a spun-up state, not a
cold start. Reconstructing the setup from `simulation_config.json` alone would initialise
the model incorrectly and fail to reproduce the trajectories. These three files are required.

## `DEM.npy` (regenerated) — channels 0 and 1 are NOT geographic coordinates

`(3, 5075, 1661)` float64, written by `preprocessing/simulation/collect_training_data.py`:

| Channel | Contents | Range |
|---|---|---|
| `[0]` | x of each cell centre, **local grid metres** | 15.0 … 49 815.0 |
| `[1]` | y of each cell centre, **local grid metres**, north-up (row 0 is the maximum) | 15.0 … 152 235.0 |
| `[2]` | elevation, metres | 153.5623 … 292.6283, `NaN` outside the watershed |

Channels 0 and 1 are built as `15.0 + arange(n) * 30.0` — a local frame, not EPSG:5070,
where the grid truly spans left 635 308.345, bottom 2 064 865.725, right 685 138.345, top
2 217 115.725. Read as projected coordinates they are wrong by ~635 km easting and ~2065 km
northing. To recover true cell centres (both identities checked against the simulator's grid
metadata to four decimal places):

```python
x_5070 = 635308.3453469264 + dem[0]     # left   + local x
y_5070 = 2064865.7248704392 + dem[1]    # bottom + local y
```

Channel 2 doubles as the active-cell mask: 4 188 840 of 8 429 575 cells are valid, the other
50.31% are `NaN`. Every trajectory array shares this `(5075, 1661)` grid, so
`~np.isnan(dem[2])` masks them all.

**One copy, not 114.** The simulator writes this identical array into every event folder,
23 GB across `sims_30`. All 114 were compared by SHA-256 and are byte-identical.

## Caveats

- **`.asc` headers are imprecise.** They give `xllcorner 635308.000000`,
  `yllcorner 2064870.000000`, against the simulator's 635 308.345 / 2 064 865.725 — off by
  0.3 m and 4.3 m. Harmless to the solver, but do not treat the header as authoritative
  georeferencing; `dem_5070.tif` carries the real CRS.
- **Unburned DEM.** Every deposited run used `burned_dem = 0`. A burned variant
  (`dem_burned_5070.tif`) exists upstream and drove none of these simulations, so it is not
  deposited.
- **Binary Manning, not the 20-class NLCD table.** `variable_manning = 0` in every run, so
  the per-class coefficients in `run_hipims_event.py` were never applied; only 0.02 / 0.05.
- Not deposited because the default configuration never reads them:
  `dem_burned_5070.tif`, `mask_largest_water_body.npy` (referenced only in commented-out
  code), `water_mask_5070.tif`, `gages.geojson`, and the EPSG:4326 variants of the DEM and
  land cover.
- The root `README.md` also lists **slope** for this folder. It is not deposited and is not
  used by the simulator; derive it from `dem_5070.tif` if needed.
